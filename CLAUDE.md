## Quality Gates

Must pass before marking any task done:

```bash
bun run fl              # oxfmt + oxlint --type-aware (boundary rules + Rule 37 await checks)
bun run type-check      # tsc --noEmit
bun run build           # production bundle
```

`bun run lint` passes `--type-aware`, which needs the `oxlint-tsgolint` devDependency — that is
what catches a Drizzle query with a missing `await` (§H Rule 37). It is slower than plain
oxlint, so `lint-staged` deliberately runs the fast variant on commit and CI runs this one.

There is **no test gate** — this repo has no test suite (AGENTS.md §E). Do not add a `bun test`
step to a checklist until one exists.

If you touched `src/db/schema/`:

```bash
bun run db:generate                    # commit the generated migration in the same PR
bash scripts/check-index-coverage.sh   # every FK column must have an index (§H Rule 32)
```

## Protected Files

Never edit without the task explicitly requiring it — see AGENTS.md "Core Files" for why:

```
src/app.ts                 ← composition root; middleware order is a contract (§I Rule 41)
src/env.ts                 ← breaks startup for everyone if the schema is wrong
src/db/index.ts            ← the real connection pool; `{ max: 1 }` here serializes every request
src/db/schema/auth.ts      ← generated by @better-auth/cli
src/db/migrations/         ← drizzle-kit generated — NEVER hand-edit (migration-guard.sh blocks writes)
src/lib/auth.ts            ← better-auth config; breaks every authenticated route
.claude/settings.json
.env* (any)
```

## Notes

- `src/modules/meta/` is the only module built to the full layer shape (service with injected
  dependencies, thin handler, route owning the contract). Copy it for new modules — **not**
  `courses/` or `payments/`, which predate these rules and skip the service layer.
- `GET /api/courses` is keyset-paginated: `{ data, nextCursor }`. It is served by the partial
  index `courses_published_created_idx`; changing its `ORDER BY` without changing that index
  turns the catalog into a sequential scan.
- On merge to `prod`, `strip-ai-on-pr.yml` removes `.claude/`, `AGENTS.md`, `CLAUDE.md`,
  `SSOT.md` from the deployed branch — these files will not exist in `prod`.

## Optional Shared Docs

Three templates ship in `.claude/` as `*.example.md`. Each covers a capability this config can use
but does not require. **Fill one in, rename it to drop `.example`, then uncomment its import line
below.** Delete the ones you do not need — an unfilled template is worse than an absent one,
because an agent will try to use it.

| Template                      | Covers                                                        | Delete it if                       |
| ----------------------------- | ------------------------------------------------------------- | ---------------------------------- |
| `DATABASE.example.md`         | Database access over MCP — topology, tunnel, production rules | You give agents no database access |
| `OPENPANEL.example.md`        | Analytics read API — base URL, auth headers, worked example   | You have no analytics backend      |
| `SERENA-WORKSPACE.example.md` | Multi-repo symbol-search scoping                              | You work in a single repo          |

```
<!-- @.claude/DATABASE.md -->
<!-- @.claude/ANALYTICS.md -->
<!-- @.claude/SERENA-WORKSPACE.md -->
```

> Note what these three are. They are **not** neutral reference material — `DATABASE.md` in
> particular is the only place recording which production operations are permitted. Treat them as
> operational rules, and review changes to them accordingly. On a backend repo that distinction is
> the difference between a debugging session and a data-loss incident.
