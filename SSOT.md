## Structure
```
src/index.ts          → bootstrap only. imports env.ts FIRST, then starts server + workers
src/env.ts            → Zod env schema. process.exit(1) on invalid
src/app.ts            → Hono instance. middleware + routes + error handler
src/modules/{name}/   → one folder per domain (auth, courses, payments, ai)
src/lib/              → service clients only (logger, redis, auth, resend, xendit, storage, trigger)
src/queues/           → BullMQ queue instances + workers
src/db/schema/        → Drizzle schema — single source of truth for DB structure
src/db/migrations/    → auto-generated by drizzle-kit. NEVER edit manually
src/middlewares/      → error, logger, rate-limit
```

## Module Structure

Every feature module must follow this exact 4-file pattern:

- `{module}.routes.ts`     → HTTP routes + OpenAPI schema definitions only. No business logic.
- `{module}.handler.ts`    → Business logic only. Calls repository methods. Never queries DB directly.
- `{module}.repository.ts` → ALL Drizzle ORM queries. No business logic, no HTTP concerns.
- `{module}.schema.ts`     → Zod request/response schemas only.

## Rules
- Never access `process.env` directly — always use `src/env.ts`
- Never use `console.log` — always use Pino logger from `src/lib/logger.ts`
- Every route must use `@hono/zod-openapi` — no plain `app.get()` without schema
- Never edit `src/db/schema/auth.ts` — auto-generated by Better Auth CLI
- Never edit `src/db/migrations/` — auto-generated by drizzle-kit
- Async work (email, notifications) must go through BullMQ — never call Resend directly from a handler
- No business logic in `src/lib/` or `src/index.ts`
- No cross-module imports — modules communicate via queues or shared lib
- Never query the database directly in handler.ts — always go through repository.ts
- Never put business logic in repository.ts — only Drizzle queries
- Never put Zod schemas inline in routes — always import from schema.ts
- Repository functions must be pure — only accept params, return data, no side effects
- Handler is the only layer allowed to call queues, external services (Resend, Xendit, etc)

## Env Variables
```
NODE_ENV · PORT
DATABASE_URL          → postgresql://user:pass@host:5432/db
DATABASE_POOL_MAX      → max Postgres pool size (production: 10)
REDIS_URL              → redis://host:6379/<db-index>
CORS_ORIGINS           → comma-separated allowlist, e.g. https://<app-host>.
                          A missing value falls back to the Zod default (localhost:3000) and
                          blocks every browser call from the real FE origin — this caused a
                          production outage on 2026-08-05. Always set it explicitly.
BETTER_AUTH_SECRET     → min 32 chars
BETTER_AUTH_URL        → https://api-<app-host>
GOOGLE_CLIENT_ID · GOOGLE_CLIENT_SECRET
RESEND_API_KEY         → starts with re_
XENDIT_SECRET_KEY
S3_ENDPOINT · S3_ACCESS_KEY_ID · S3_SECRET_ACCESS_KEY · S3_BUCKET_NAME
TRIGGER_API_KEY
SENTRY_DSN             → optional; SDK is wired but unset in production (not yet active)
```

`AI_ENGINE_URL` and `XENDIT_WEBHOOK_TOKEN` do not exist in this repo's environment — this repo
never calls the AI service, and no webhook token is configured for Xendit callbacks.
